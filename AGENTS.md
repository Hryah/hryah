# Інструкції для AI-агентів

Це репозиторій гри hryah для NASA Space Apps 2026 (TypeScript, Vite, React). Над ним одночасно працюють шестеро людей і кілька агентів, кожен у своїй частині. Твоя задача — зробити свою частину так, щоб вона стикувалась з іншими без ручного виправлення.

## Спочатку прочитай

1. `docs/ARCHITECTURE.md` — як влаштована гра і що куди класти.
2. `REVIEW_RULES.md` — правила, які перевіряє CI.
3. `src/core/contracts.ts` — спільні типи. Це джерело правди, поля беремо звідси, а не з пам'яті.
4. `src/core/stub-phases.ts` — зразок того, як виглядає частина гри.

## Де можна писати

Людина в завданні назве твою частину: `design`, `flight` або `orbit`. Тоді твої теки:

- `src/core/<частина>/` — логіка;
- `src/ui/<частина>/` — екран;
- `src/core/phases.ts` — один рядок, що підключає твою частину замість заглушки.

Усе інше не чіпай без прямого прохання людини. Особливо:

- `src/core/contracts.ts`, `src/core/game.ts`, `src/core/physics.ts`, `src/core/stubs.ts`;
- теки інших частин;
- `.github/`, `deploy/`, `scripts/`, `package.json`.

Якщо для роботи бракує поля в контракті або функції в `physics.ts`, зупинись і скажи людині, що саме потрібно і навіщо. Не дописуй сам і не обходь через `any` чи власну копію типу.

## Як писати частину

Частина — це об'єкт, що реалізує `Phase<In, State, Action, Out>` з `contracts.ts`. `In` та `Out` вже задані (`DesignPhase`, `FlightPhase`, `OrbitPhase`), свої `State` і `Action` визначаєш сам.

- `step(state, action)` чиста: повертає новий стан, вхідний не мутує.
- Стан — звичайні JSON-дані. Без класів із методами, `Map`, `Set`, функцій, `undefined` у значеннях.
- Час приходить дією `{ type: 'tick', dtS }`. У ядрі немає годинника.
- Рандом лише через `nextRandom(state.rngState)` з `physics.ts`, новий `rngState` кладеш у стан.
- Одиниця виміру в назві поля: `massKg`, `powerW`, `chargeWh`, `bufferMb`, `periodS`.
- Кожна відмова записується в журнал як `CauseEntry` з `kind: 'failure'` і непорожнім `causedBy`. Формат id і приклади є в розділі 7 архітектури.
- Реалізуй `debugActions(state)`: без нього в частину не можна грати на дебаг-екрані.
- Тексти для гравця не пишемо в коді. У стані й журналі лише ключі (`messageKey`), самі тексти англійською у файлі текстів.
- Екран лише читає стан і шле дії. Жодних розрахунків у компонентах.

## Пастки CI

Крок `core purity` шукає в `src/core/` заборонені слова звичайним grep, тому спрацьовує навіть на коментарі. У файлах ядра (крім `*.test.ts`) не повинно бути слів `window`, `document`, `localStorage`, `requestAnimationFrame`, викликів `Math.random(`, `Date.now(`, `performance.now(` та імпортів `react`, `react-dom`, `three`, `pixi.js`, `zustand`.

Проєкт зібраний із `noUncheckedIndexedAccess`: елемент масиву чи запису за індексом має тип `T | undefined`, його треба перевіряти. Імпорти пишемо без розширення: `from './contracts'`.

## Ігрові рішення

Що саме відбувається у твоїй частині (які дії, події, умови перемоги, цифри), вирішує людина і дає списком у завданні. Якщо чогось у списку немає, а без цього не можна рухатись, запитай. Не вигадуй ігрові правила мовчки: інші частини на них не розраховують.

Якщо вибір дрібний і зворотний (назва поля у власному стані, порядок кнопок), вирішуй сам і згадай про це у звіті.

## Коли робота готова

Перед тим як сказати «готово», запусти й переконайся, що все зелене:

```bash
npm run typecheck
npm test
npm run build
```

І перевір список:

- [ ] є тести на `step`: не мутує стан, детермінована за сідом, стан переживає `JSON.parse(JSON.stringify(...))`;
- [ ] є тест, що проходить частину від `init` до `isDone` і перевіряє `finish`;
- [ ] частина підключена в `phases.ts`, і `src/core/game.test.ts` досі зелений;
- [ ] гра проходиться на дебаг-екрані (`npm run dev`) від початку до розбору;
- [ ] у журналі немає відмов без `causedBy`.

Якщо тест падає, виправляй код, а не тест. Не послаблюй і не видаляй чужі тести, щоб пройти перевірку. Якщо чужий тест здається помилковим, скажи людині.

## Git

- Працюй лише в гілці `feature/<хто>-<що>`. У `main` та `experimental` не пуш і нічого туди не зливай.
- Коміть малими змістовними шматками. Без `--force`, без переписування історії.
- Не додавай залежності без дозволу людини.
- Секрети в код не потрапляють.
