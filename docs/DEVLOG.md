## 2026-11-14 — Етап 0: відтворювані джерела й передача розробнику

**Статус: реалізовано й перевірено локально; підготовлено до feature-коміту.**

- Гілка: `feature/nikita-foundation`.
- База: `cc82c1d` з `origin/experimental` на початку роботи.
- Коміт цієї зміни: ще не зафіксований у цьому записі; злиття й публікація не підтверджені.

**Що зроблено й навіщо:** повернуто редагований генератор майстерні з окремої локальної копії до `tools/asset-workshop/`, разом із залежностями, генераторами, тестами й виправленнями публічного сайту. Це прибирає залежність від локальної копії та дозволяє зібрати пакет із нового клону. `nikita models/` лишається згенерованим знімком для перегляду й завантаження.

Збережено всі п'ять оригінальних SVG космонавта у `art/astronaut/source/`. `source-manifest.json` описує походження, контрольні суми та чотири вибрані ракурси; `validate-sources.mjs` перевіряє джерела. Основний передній вид відповідає оригіналу «космонавт перед (2).svg». Файли ще мають вихідний фон і різний масштаб: це збережені оригінали, а не готові runtime-спрайти чи анімації.

Задокументовано затверджені рішення: справжній 3D-світ, мальований 2D-персонаж, ортографічна ізометрія, WASD + E, основний режим однієї місії. `AGENTS.md` містить короткий стан і наступне завдання; повні етапи й історія живуть в окремих документах. Додано вкладені інструкції для джерел космонавта, майстерні, графіки й орбіти; оновлено застарілі описи маршрутів і специфікацію орбіти.

**Інтерфейси та процес:** канонічний запуск із кореня — `node tools/asset-workshop/scripts/reproduce.mjs`: встановлення за lockfile → перевірки → генерація → збірка → повний ZIP → знімок `nikita models/`. Оригінали космонавта окремо перевіряються командою `node art/astronaut/validate-sources.mjs`. Залежності майстерні ізольовані; перевірки головної гри не повинні випадково запускати тести її пакета. Контракти ігрових фаз на цьому етапі не змінюємо.

Перенесено заголовок, адаптивну верстку й share/download публічного сайту у джерела. Копіювання одразу показує адресу навіть при очікуванні Clipboard API; ZIP містить скомпільований переглядач і справжній адаптер. Прибрано недійсний fallback із вихідним HTML. Нормалізація LF і сталі часові мітки ZIP прибирають залежність від переносів рядків. Генератор очищує лише власну теку моделей від старих GLB; виходи збірки перевіряються на перенаправлення junction/symlink до очищення. Root Vite сканує лише index.html, root Vitest не запускає ізольовані тести майстерні.

**Фактичні перевірки (успішні):**

- Чистий експорт staged Git tree без локальних ресурсів і node_modules: `npm ci`, `npm run typecheck`, `npm test` — **18 файлів / 222 тести**, `npm run build -- --base=/experimental/`. Root перевірено до встановлення залежностей майстерні.
- `node art/astronaut/validate-sources.mjs` — усі 5 SHA-256, розміри й чотири затверджені ракурси; оригінали зберігаються без зміни байтів.
- З того самого чистого дерева `node tools/asset-workshop/scripts/reproduce.mjs` — власний npm ci, типи, **12 Vitest + 8 Node тестів**, генерація, збірка, перевірка й оновлення знімка.
- Чистий GLTFLoader повторно завантажив **25 моделей / 139 кліпів** із фактичного ZIP; **13 108 трикутників** у наборі. Архів має 59 файлів, скомпільовані JS/CSS, матеріали, маніфест та адаптер; приватні інструкції й сам архів до нього не входять.
- Знімки з робочого дерева Windows і чистого Git-експорту побайтово однакові. ZIP: **692 137 байтів**, SHA-256 `7c0c183cfd087020da484eb01bc965c785f58965be9fcef1d04e66fd033102fd`.
- Перевірено альтернативний експорт `exports/release`, відносні URL для `/` і `/experimental/`, відсутність старих моделей, збереження захищеного файла при junction та рівність ZIP для LF/CRLF. Незалежне рев'ю підтвердило виправлення двох знайдених проблем генерації/шляхів.
- У браузері: вибір моделі, програвання run, камери, верстка 1280/900/600 px, copy-link, фактичне завантаження ZIP; SHA завантаження збігається. Розпакований завантажений переглядач відкрито окремо через HTTP без встановлення його залежностей.
- У поточній грі вручну перевірено #play до успішного розбору й новий забіг із малою батареєю до провалу; журнал посилається на вибір батареї та камери. Це перевірка наявного runner із заглушкою орбіти, а не нової інтегрованої гри.
- Перевірено локальні посилання основних документів і `git diff --check`.

**Обмеження:** новий 3D-рендер і прозорі спрайти ще не реалізовані; справжня орбіта не підключена до `#play`. Повний перегляд усіх кадрів і незалежний Khronos Validator не проводилися; автоматичний аудит не гарантує відсутність усіх візуальних артефактів. У переглядачі верх моделі космонавта при типовому масштабі може перекриватися панеллю інструментів. Архів не містить сам себе, тому повторне завантаження повного пакета з офлайн-копії недоступне; окремі моделі експортуються. Публічний сайт не перепубліковувався.

**Наступне одне завдання:** етап 1 — невелика справжня 3D-кімната з чотирма статичними ракурсами космонавта, WASD-рухом, зіткненнями й одним пультом, що відкривається через E.

## 2026-11-14 — Перевірена базова точка перед етапом 0

**База: `cc82c1d`, гілка `experimental`.** Це вже наявний стан коду, а не нова реалізація в `feature/nikita-foundation`. Відповідність розгорнутого сайту цьому коміту окремо не підтверджена.

- `#play` є типовим маршрутом: справжнє проєктування → справжній політ Макса → орбітальна заглушка → причинний розбір із новим забігом.
- `src/core/phases.ts` підключає справжні дизайн і політ; справжній `src/core/orbit/` працює окремим прототипом `#orbit` з демонстраційними збірками. Його тумблери й прогноз не є частиною місії з `#play`.
- Політ уже містить фізику невагомості, поручні, зіткнення, пульти, кризи та мініігри. Наявну роботу адаптуємо замість повторної реалізації. Рендер польоту й переглядач GLB використовують Canvas 2D; справжнього 3D-світу з авторським 2D-персонажем ще немає.
- `FlightResult` містить орбіту, залишок палива й пошкодження, але не статус відділення або втрати. Виконавець завжди переходить до орбіти після завершеного польоту; `GAME_OVER` сам не встановлює `phaseDone`. Це завдання інтеграції етапу 2.
- Консорціум, його аналіз і `sim.ts` використовують заглушки. Виробничий дефект уже застосовується до специфікації один раз; нові пошкодження польоту мають передаватися окремо.
- Чинний SAFE орбіти вимикає камеру й передачу, дозволяє доступний обігрів і не зменшує базове споживання. Допоміжний `netPowerW` має суперечливе правило; відкрита розбіжність D9 описана в [MODEL.md](MODEL.md).
- `src/storage.ts` має JSON-збереження з префіксом каналу, але збереження забігу `#play` і версія формату ще не підключені.

**Перевірка цієї точки:** огляд коду, контрактів і документації. Цей запис не заявляє новий запуск автоматичних тестів, збірки або перевірку опублікованого сайту.
