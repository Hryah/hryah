# Мальований космонавт

Етап 0 зберіг усі п'ять оригінальних SVG без зміни байтів. SHA-256, початкові
розміри та відповідність оригінальним назвам записано в `source-manifest.json`.
Статус цього маніфесту — `raw-source`: він описує оригінали, а не їх похідні.

Для етапу 1 підготовлено **чотири прозорі статичні текстури** та runtime-маніфест
у `public/assets/astronaut/`. Підготовка відтворюється без додаткових залежностей.
Справжні анімації ще не створено.

## Затверджені ракурси

- `source/front.svg` — основний передній вид, оригінал «космонавт перед (2).svg».
- `source/back.svg` — вид ззаду.
- `source/left.svg` — вид ліворуч.
- `source/right.svg` — вид праворуч.
- `source/front-alternate.svg` — збережений альтернативний передній вид;
  він не вибраний основним.

Гра використовує мальованого **2D-персонажа, орієнтованого до камери**, у
справжньому 3D-світі. Камера — фіксована ортографічна ізометрія. Перша платформа —
браузер на ПК; переміщення — WASD, взаємодія з пультом — E. Готовий GLB-космонавт
із майстерні є допоміжним матеріалом і не замінює цього персонажа в ігровому рендері.

## Підготовка статичних текстур

У вихідних файлах різні розміри полотна й суцільний сіро-блакитний фон. Генератор
`scripts/astronaut/prepare.mjs` перевіряє контрольну суму кожного вибраного джерела
й видаляє лише перший path, якщо той має очікуваний колір і точно покриває все
початкове полотно. Інші path зберігаються дослівно: білий шолом, рюкзак, світлі
деталі скафандра й темна обводка лишаються на місці. Це редагування векторних
елементів, без растрового стирання кольорів.

Межі персонажа обчислюються за справжніми екстремумами кубічних кривих. Усі
чотири види мають полотно 1024×1024, видиму висоту 840 px і нижню центральну
точку опори `(0.5, 0.92)` — `(512, 942.08)` px. Один рівномірний transform
зберігає пропорції кожного малюнка; прозорі поля залишають місце довкола обводки.
Генератор не змінює `source/` і не використовує альтернативний передній вид.

Результат — `public/assets/astronaut/{front,back,left,right}.svg` і
`public/assets/astronaut/runtime-manifest.json`. Маніфест містить напрямок,
`idle`/`move`, кадри, fps, loop, опору, розміри, вихідні й нормалізовані межі та
контрольні суми. Шляхи `assets/astronaut/front.svg` тощо відносні до базової
адреси застосунку, щоб працювати також під `/experimental/`.

Для площини у 3D видима висота персонажа дорівнює висоті площини × `840 / 1024`.
Опора вказує низ персонажа; центр площини треба підняти над нею на
`(0.92 - 0.5) × висота площини`. Підготовлені файли не редагуємо вручну.

## Що ще потрібно підготувати

Бічні ракурси є статичними позами з піднятою ногою. Це не готовий цикл бігу,
плавання чи роботи руками. Розкладення на іменовані 2D-шари або додаткові кадри
та справжні анімації належать етапу 3. Поки обидва стани `idle` і `move` явно
використовують той самий один статичний кадр: `fps: 0`, `loop: true`,
`staticPose: true`; загальний `animationReady: false`. Ці поля дозволяють UI
вибирати ракурс, але не заявляють готовий цикл руху. Справжні кадри й дії можна
додати до тієї самої структури маніфесту після їх авторської підготовки.

## Перевірка з нового клону

З кореня репозиторію, без зовнішніх файлів і додаткових залежностей:

```sh
node art/astronaut/validate-sources.mjs
node scripts/astronaut/prepare.mjs
node scripts/astronaut/prepare.mjs --check
node --test scripts/astronaut/prepare.test.mjs
```

Перша команда перевіряє оригінали, розміри, SHA-256, вибрані ракурси та
відсутність очевидних скриптів/зовнішніх посилань. Друга відтворює похідні файли;
`--check` лише перевіряє, що вони точно відповідають генератору. Тести перевіряють
межі кривих, детермінізм, збереження всіх path персонажа й світлих деталей,
видалення фонового path, однакову опору, контрольні суми та чесні статичні стани.
`.gitattributes` похідних файлів фіксує LF для однакових байтів на різних системах.

Для візуальної перевірки потрібен браузер: чотири ракурси на контрастному фоні,
відсутність непрозорого прямокутника чи його уламків, збереження білих деталей,
спільна опора й правильне перекриття обладнанням. Автоматична перевірка джерел
не є повним SVG-санітайзером чи тестом майбутніх анімацій.
